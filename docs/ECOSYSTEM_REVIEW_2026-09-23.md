## Current communication map and incremental migration

- Rig exposes two **separate loopback WebSocket services**: Studio command port 47777 and Viz direct port 9460. Studio probes the loopback Rig peer with bounded backoff, performs a version-1 hello when present, and allows manual disconnect without an immediate reconnect. The Viz direct stream sends semantic fixture frames, not raw ArtDMX. Neither requires opening VizBridge. Loopback restriction intentionally prevents unauthenticated LAN control; LAN pairing has not been designed.
- Studio/Stage have a separate version-1 `luma.show`/shared-show transport targeting port 47321 and local browser events. A default WebSocket URL does **not** prove a broker exists or that frames arrive. Stage marks Studio connected from a received show frame and times out after three seconds. Its Viz presence is metadata, not a pixel receiver acknowledgment.
- LumaLink handles **external** MIDI endpoints, MIDI clock, panic and device routing. Existing NDI runtime detection does not make Stage an NDI sender.
- VizBridge currently handles DMX transport/monitoring. Add native LUMA peer discovery and typed contracts in a shared library first. VizBridge can then provide optional routing/advanced diagnostics while direct peers remain independent. Do not route bulk DMX and full-resolution pixels through a JSON control bus.

Suggested contract for a new `luma.control.v1` envelope: `schemaVersion`, `messageId`, `source` (app/instance), `destination`, `showId`, `sentAt`, `sequence`, `type`, `capabilities`, and a discriminated `payload`. Hello negotiates application/version/capabilities. One authoritative owner is specified for each writable show domain. Commands with side effects have bounded correlation IDs, deadlines, structured acknowledgment, and a deduplication window across reconnect when persistence exists. Presence/health have monotonic heartbeat timeout. State reconnection requires an explicit revisioned snapshot, then ordered deltas; missing revisions request a new snapshot. High-rate DMX/preview frames use a negotiated stream and latest-frame replacement with bounded queues, so slow subscribers never block the engine. Unknown commands/schema major versions fail closed and surface an actionable error. This is a migration design, **not an implemented ecosystem protocol**.

For one machine, advertise endpoint + version through an app-owned local registry or Unix-domain socket with lifecycle cleanup; a localhost WebSocket remains a practical control connection. On a LAN, mDNS can advertise peers but actual connections need authenticated pairing, explicit interface selection and operator confirmation for control authority. Do not automatically trust a discovered address. Apps should connect directly by default and register with VizBridge/Hub when present. Stage screen routes require `screenId`, output surface, source, destination, transport, resolution/FPS, current frame, last receiver acknowledgment, latency and fallback. A local preview does not count as a connected output.

### LumaHub decision

A visible **diagnostic viewer backed by an optional per-host service** is the best next shape; the viewer can close without interrupting shows. Start with read-only app health/presence, connection graph, dropped frame/audio/DMX counters, bounded structured logs and a redacted export bundle. Include timestamps, instance IDs, show IDs, command correlation, reconnect reason and queue depth. Capture crash breadcrumbs to disk before centralized ingestion. LumaHub must never become the only discovery or playback path. GPU/VRAM and transport loss metrics require native measurements; do not populate decorative zeros. No Hub implementation is claimed in this checkpoint.

## Verification and residual risk

Frontend tests and production TypeScript builds were run individually for Rig, Studio, Viz and Stage. Rig's native bridge and fixture serializer have isolated Rust TCP/WebSocket tests covering repeated disconnect, duplicate IDs, malformed hello, command timeout, nonblocking accepted sockets and two clients using the same ID. macOS CI exposed an accepted-socket mode difference that local Linux tests had missed; the fix is in the Rig review branch and its next CI run must pass before the native bridge is considered verified. Studio, Viz and Stage review CI passed for their previous checkpoints; new Studio changes still need macOS CI. This workspace cannot certify macOS CoreAudio, hardware MIDI, DMX devices, external video or a real receiver. Browser navigation to local Vite via the provided cloud browser was blocked, so interactive pixel-level and cross-app desktop trials remain unverified. Verify compiled artifacts in CI, then on the target Mac.

The Viz production build currently emits an approximately 8.25 MB main JavaScript asset (1.89 MB gzip) and took about 2 minutes 52 seconds to bundle in this container. That is a measured distribution/launch-risk signal, not proof of runtime FPS. Profile actual cold-start, parse time and scene render before refactoring its Babylon imports.

Show-stopping gaps still include native audio device/output validation, explicit panic and restore, autosave and missing-media relink, long-running load and reconnect tests, fixture personality equivalence across Rig and Viz (the tested RGBWAUV and 16-bit vectors now agree; CMY, wheel slots, shutter behavior and gobos remain), LumaStage video/import/busking, real screen transport/acknowledgment, and a common capability/discovery protocol. The Stage unsupported generator looks now fail closed. Studio can start an empty service, add items and sections, and check assigned files, but the full rehearsal-to-live workflow still needs testing and recovery. Studio's Section Session uses one aligned song transport and is **not** a full independent Ableton-style clip grid. These constraints must be resolved before claiming a live-service-ready ecosystem.

Next integrated test: build a test show with >20 mixed fixtures, two universes, moving pan/tilt fine channels, RGBW, Studio multitrack and count-in, Stage screens and a Viz scene. Start apps in varied orders. Pull/reinsert Rig↔Studio and Rig↔Viz connections, inject malformed messages, run fast faders/cues, stop and restart apps, record actual sender/receiver states and observed audio/DMX/video output. Run on a Mac with the intended interfaces, renderer and output devices; instrument dropped frame, render frame time, audio underruns and queue depth. This checkpoint does not claim that test was run.
